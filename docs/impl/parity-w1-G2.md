## Implemented

C6/C7 are in `src/sync/text.ts`. The exported `TextContext`, `textToHtml(text, context?)` and `htmlToText(html, context?)` signatures are stable for G3's mirror integration. Mapped mentions use Plane's rich mention element; unmapped logins link to the configured host and unmapped Plane users use the supplied display name. Local, qualified and same-host full issue references use canonical labels and links. Code, explicit link labels and image alt text stay outside enrichment. Tables/alignment, image alt/title, bare URLs, soft wraps, inline code and fenced code have authored round-trip regression cases. Markdown-generated HTML is escaped and only absolute HTTP(S) destinations become active links/images. User lookups share promises within one conversion and never cache across conversions/workspaces. Unmatched backtick runs are consumed together; qualified-reference scans start only at a token boundary.

G3 owns `src/sync/mirror.ts` and has wired its descriptions/comments to this converter. I did not edit that file.

The browser-build fix moves every failure-report helper/type into new server-only `src/github/problems.ts`, using a static Node crypto import there. `pr-automation.ts` retains the browser-shared lifecycle configuration helpers and has no report-helper/Node crypto import. Push/check callers and the G2 regression tests import the server module directly.

N2 producer/helper work:

- The current mapping opt-in is read with the exact workspace, mapping, repository and installation tuple, including the workspace installation allow-list. A missing opt-in is false.
- GitHub reports are outbox plans with frozen authority, a stable remote marker for the source/target, and immutable content-version intent keys. Same failure/body reuses its intent; a changed message updates the same remote comment. No reducer posts directly.
- The executor reads the entire existing comment collection before mutation, refuses incomplete reads, and identifies reports by both marker and the authenticated App bot login/type. A matching existing body recovers a lost POST receipt without another POST. A changed body PATCHes the same comment identity. Commit comments and PR discussion comments use their respective REST routes.
- Known Plane targets get escaped service-comment plans marked with `_problemReport` for consumer dispatch/recursion prevention with stable per-source failure keys and an explicit target. A foreign workspace is refused.
- Smart Commit producers cover malformed `#time`, missing/ambiguous state, unknown work-item keys, signature rejection, incomplete push ranges and permanent command failures. Reports aggregate messages into one commit notice, keep known-item diagnostics specific to their Plane target, and omit raw transport/API error bodies and project identifiers. Retained failed-step audits restore registration after a reporting failure without re-running finished commands.
- Failed check-suite/deployment automation registers a Plane notice on the targets named in its failed audit rows; other linked targets are excluded. A notice-registration failure during an already-failed rule preserves the original error and retry deadline.
